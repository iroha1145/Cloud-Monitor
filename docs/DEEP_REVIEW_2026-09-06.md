## 修复明细

P1 表示应优先处理的数据完整性或生命周期问题；P2 表示功能、健壮性和配置保护问题。此分级不是漏洞评分，也不意味着已经发生线上入侵。

| 编号 | 优先级 | 位置 | 原问题、影响与修复 |
|---|---|---|---|
| R01 | P1 | `hub/backend/hub/tm_proxy.py` | 设备 ID 解码后直接插入上游 URL。删除 `gpu?backup` / `gpu#backup` 时可能删除 `gpu`，带 `/` 的设备则无法删除。转发时重新编码路径段，路由支持完整 ID；真实官方 Node hub 测试覆盖问号、井号、斜杠、中文，百分号另用真实 HTTP 验证。 |
| R02 | P1 | `services.py`、`db.py` | 旧指纹以 `|` 拼接字段，`("a|b", "c")` 与 `("a", "b|c")` 可产生相同指纹，使不同同步记录被判为重复，游标继续前进。数据库和同批去重均改为比较完整不可变字段；保留旧指纹存储格式，不需要迁移或清空历史，旧记录重试仍幂等。 |
| R03 | P1 | `tm_proxy.py`、`tm_outbox.py` | 后台线程最多等待 5 秒，但上游请求可能仍在运行；生命周期随后关闭 HTTP 客户端及 SQLite，出现退出竞争。现在等待当前工作完成，并在队列项目之间响应停止信号，未处理项保留 pending；后台首次初始化异常也进入重试，而不是让线程退出。 |
| R04 | P1 | `tm_update.py` | 并发更新请求可能同时通过空闲检查，竞争同一个临时文件；宿主机看到请求后写入的 running 状态也可能被网关后写的 queued 覆盖。新增提交锁、独立临时文件，仅原子发布请求，再按请求 ID 推导 queued；宿主机进度保持独立。旧版只写了 queued 却未发布请求的遗留状态允许重试，发布失败返回 503。没有执行真实宿主机更新。 |
| R05 | P2 | `tm_overview.py` | 写入使缓存失效后，之前尚未完成的 overview 请求仍能把旧数据重新放回缓存。增加线程安全的缓存代数检查，旧请求不得重新填充已失效缓存。 |
| R06 | P2 | `config.py` | `ACCESS_TOKEN` 没有执行其他密钥已有的长度及弱值校验，`password` 等配置能启动。统一校验，显式允许的共享密钥回退仍保留。长度检查不能替代随机性，部署应使用随机密钥。 |
| R07 | P2 | `body_limit.py` | 请求体缓冲回放结束后不停返回空 `http.request`，吞掉真正的断连消息。回放结束后恢复原始 receive；超大分块先检查长度再复制。 |
| R08 | P2 | `main.py` | 在线更新 POST 不在实际请求体限额内，鉴权前可解析多余的大 JSON。新增 4096 字节限额，不依赖 Content-Length。 |
| R09 | P2 | `main.py` | 就绪检查捕获 SQLite 失败后，又无保护地读取快照状态，导致结构化 503 变成未处理的 500。快照失败纳入组件状态；存活检查仍能单独返回 200。 |
| R10 | P2 | `main.py` | 配置了跨域来源，预检却不允许官方使用的 `X-Token-Monitor-Secret` 请求头。补齐允许头，不扩大允许来源；不受信任来源仍被拒绝。 |
| R11 | P2 | `hub/dashboard/src/api.ts` | 请求依赖可选的 `AbortSignal.any/timeout` 静态方法；响应体读取不在超时错误处理内。改为独立控制器、定时器和取消监听，覆盖 JSON 读取并清理资源，保留调用方取消原因。 |
| R12 | P2 | `data.ts` | 趋势仅检查日期非空。无效日期可能污染最近日期范围、让整条趋势消失，或被日期解析器进位为另一天。复用严格日历日期校验，闰日按真实日期保留。 |
| R13 | P2 | `styles.css` | 长名称使弹窗网格按最小内容宽度扩张。390 像素视口实测弹窗内部宽约 1397 像素、可用宽 356 像素。改为可收缩单列及长文本换行；修复后两者均为 356 像素，未靠隐藏横向溢出掩盖问题。 |
| R14 | P2 | `InsightTrend.tsx`、`trend-math.ts` | 曲线插值用零作为下界，抹掉负数费用；普通平滑还可能制造记录之外的峰谷。保持已有曲线形式，将插值限制在相邻真实记录范围内，保留每个真实节点与负数费用。 |
| R15 | P2 | `agent/requirements*.txt`、CI | Requests 仍锁定 2.32.3，CI 有两项审计豁免。升级至官方发布的 2.34.2，同步对应 wheel 哈希，移除豁免；具体依赖安全扫描以本 PR 的 CI 日志为准，不把所有公告都等同于本项目可利用漏洞。 |

## 升级与边界

升级前检查 `ACCESS_TOKEN` 至少 32 字符且不是弱默认值，推荐强随机值。之前不足长度的配置会被拒绝启动；既有合格密钥无需更换。不要把 `.env`、密钥或生产数据库上传到 PR。

不改数据库 schema、同步协议、数据总量定义或官方 vendored Node 核心；没有重建数据库或删除历史。升级仍建议保留正常部署备份。前端构建产物本来就不跟踪，本次修改由既有 Docker 多阶段构建重新生成。

保留的后续工作：前端主包仍触发 500 kB 的构建体积提示，拆包需要独立评估交互及加载顺序；现有 `agent/requirements-lock.txt` 是单平台锁，Docker 尚未启用跨平台哈希锁，本次只同步 Requests 条目。没有宣称这两项已经解决。

本次重点为 Web 前后端、同步代理、依赖和部署接线；未进行 Android 真机验证，也未对线上服务进行负载或破坏性测试。自动测试和审查不能证明项目绝无其他缺陷。
