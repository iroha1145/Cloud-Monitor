## 补充发现

| 编号 | 优先级 | 位置 | 复现与修复 |
|---|---|---|---|
| R16 | P2 | `hub/backend/hub/main.py` | 无效计数 `NaN`、`Infinity`、`-Infinity` 或 `1e9999` 被输入校验拒绝后，错误对象仍含原始值；原异常处理器再次序列化该对象，导致 JSON 响应生成失败，返回 500。现在只返回错误类型、位置和说明，稳定返回 400，也不回显输入对象或校验上下文。正常成功响应不变。 |
| R17 | P2 | `models.py`、`services.py` | 某些字符串日期本身合法，但转换为 UTC 后超出可表示年份，例如 `0001-01-01T00:00:00+14:00` 和 `9999-12-31T23:59:59-12:00`。同步及查询过滤会出现未处理的溢出。现将解析、时区归一化和边界异常统一纳入校验，返回 400；合法东京时区时间仍能正常入库、查询和往返。 |
| R18 | P2 | `services.py` | 极大页码计算出的 OFFSET 超过 SQLite 有符号整数范围，导致 500。现先与记录总数比较，超出范围直接返回空页，无需将超大整数绑定到 SQL。 |

这些接口仍遵守既有鉴权，以上现象不是绕过鉴权或远程代码执行的证据。
