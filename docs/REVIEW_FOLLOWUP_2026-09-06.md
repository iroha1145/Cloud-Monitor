## 补充发现

| 编号 | 优先级 | 位置 | 复现与修复 |
|---|---|---|---|
| R16 | P2 | `hub/backend/hub/main.py` | 无效计数 `NaN`、`Infinity`、`-Infinity` 或 `1e9999` 被输入校验拒绝后，错误对象仍含原始值；原异常处理器再次序列化该对象，导致 JSON 响应生成失败，返回 500。现在只返回错误类型、位置和说明，稳定返回 400，也不回显输入对象或校验上下文。正常成功响应不变。 |
| R17 | P2 | `models.py`、`services.py` | 某些字符串日期本身合法，但转换为 UTC 后超出可表示年份，例如 `0001-01-01T00:00:00+14:00` 和 `9999-12-31T23:59:59-12:00`。同步及查询过滤会出现未处理的溢出。现将解析、时区归一化和边界异常统一纳入校验，返回 400；合法东京时区时间仍能正常入库、查询和往返。 |
| R18 | P2 | `services.py` | 极大页码计算出的 OFFSET 超过 SQLite 有符号整数范围，导致 500。现先与记录总数比较，超出范围直接返回空页，无需将超大整数绑定到 SQL。 |
| R19 | P2 | `hub/dashboard/src/styles.css` | GitHub 浏览器截图中的通知条向右偏移，手机上内容和关闭按钮可能超出视口。Motion 写入的内联 transform 覆盖了 CSS translateX(-50%)。改为左右边界与自动外边距居中，动画单独控制 transform，并允许长文案换行、保护关闭按钮。新增 320、390、1440 像素宽度下普通／减少动态效果共六项浏览器回归。 |

这些接口仍遵守既有鉴权，以上现象不是绕过鉴权或远程代码执行的证据。

## 合并前复核：在线更新中断恢复

复核 PR 提交 `58ded9ac0d97e02e3f00f11623f46fc4bdb3cca3` 时确认，R04 的两次文件写入之间仍存在中断窗口：进程退出会留下 queued 状态，却没有供宿主机消费的请求；重启后查询一直显示排队，再次提交返回 409。

补充修复只改在线更新服务：以 `request.json` 的原子发布作为唯一提交点，查询按请求 ID 识别新任务并生成 queued 状态，不再预写 queued 覆盖宿主机状态。对于旧版遗留的“queued 且无请求”状态，显示可重试错误。已发布的请求在服务重启后仍阻止重复提交，宿主机的 running、ok、error 状态继续保留。

新增 `tests/test_tm_update_recovery.py`，包含真实子进程在首次发布后立即退出、旧状态经 HTTP 重试、已有或损坏状态文件、服务重启去重及宿主机完成清理，共 9 项用例。修复前为 6 失败、3 通过；修复后与现有在线更新测试及 3 项并发／写入失败回归合计 **25 项通过**。本地使用 Python 3.12.13 和仓库声明的依赖，仅运行本次修改涉及的测试，原有整套结果沿用此前流水线记录。
